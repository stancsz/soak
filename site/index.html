BOUNDED BY DESIGN

Every run has
an exposure limit.

Soak is a small runner, not a benchmark that invents a definition of success. You supply the harness and evaluator; the configuration defines how long and under what gates to run.

01

Set the window

Choose duration, per-iteration timeout, interval, drain window, and optional run cap.

02

Keep each outcome

The event log flushes every iteration; the summary stores counts, p95 latency, and gate violations.

03

Review the failures

Compare repeated results with model/harness versions and resource measures you collect.

WHAT THE FRAMEWORK DOES NOT DO

A runner is only
as good as its adapter.

Soak does not grade semantic quality, enforce provider spend, or prove that a persistent harness recovered after failure. Put those checks in a trusted adapter and record the environment separately.

See alternatives and the validation plan ↗
01

Not a load generator

Iterations are sequential. Use a dedicated load-testing tool when concurrent service pressure is the question.

02

Not a model grader

A pass is the adapter's boolean. Add independent checks for correctness, regressions, and recovery.

03

Not unlimited

Set provider-side spend limits. The framework does not enforce request budgets or own adapter child processes.
